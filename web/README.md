# web/ — AutoDeploy AI dashboard

React (Vite) frontend for Stage 4. **Demo mode only so far** — live mode
(health check + real repo/SHA input against the backend) is a separate,
not-yet-built phase; see the root [README](../README.md#stage-4-dashboard)
for status.

## Structure

```
src/
  components/    one .jsx + co-located .css per component
  lib/            driverLabels.js — plain-language SHAP explanations (JS port
                  of .github/scripts/post_prediction.py's mapping)
  data/           demoFixtures.json — real captured model outputs (see below)
  styles/         tokens.css — design tokens (colors, spacing, type)
```

## Run it locally

```bash
cd web
npm install
npm run dev      # http://localhost:5173
npm run build    # production build to dist/
```

No backend needs to be running for demo mode — it's fully self-contained.

## The demo fixtures — how they're real, not fabricated

`src/data/demoFixtures.json` is generated by
[scripts/09_generate_demo_fixtures.py](../scripts/09_generate_demo_fixtures.py),
never hand-edited. Every one of its 4 examples is a genuine inference from
the actual trained model (`outputs/models/hgb_split_temporal.joblib`) —
nothing in the output JSON is invented. What differs between examples is
only where the *input* feature vector came from:

| Example | Input source | Real? |
|---|---|---|
| Real repo, healthy history | Live GitHub extraction (`spf13/cobra`, Stage 3 Layer 2) | Fully real, end-to-end |
| Active failure streak | Hand-specified vector, identical to `tests/test_post_prediction.py`'s `VALID_PAYLOAD` | Real model output on a chosen-to-illustrate input |
| Brand-new repo, first build | Hand-specified vector, identical to `tests/test_post_prediction.py`'s `COLD_PAYLOAD` | Real model output, real `cold_start` branch |
| PR build, unrecognized language | New hand-specified vector (not backed by a live pull — see script docstring for why) | Real model output on a chosen-to-illustrate input |

Regenerate with `python scripts/09_generate_demo_fixtures.py` (from the
project root, venv activated) whenever the model is retrained.

## Design notes

The brief asked to load a "frontend-design" skill before styling it — no
such skill exists in this environment (checked; only `design`,
`dataviz`, `artifact-design`/`artifact-diagramming`/`artifact-capabilities`
are available, none of which fit a hand-coded React app). Flagged rather
than silently substituted. Styling was done by hand instead: muted,
desaturated palette (no risk-tier color reads as alarming), a monospace
face reserved for technical figures only, generous whitespace, no
gradients/shadows beyond a minimal card elevation — aimed at "credible
engineering artifact," not a product landing page.
